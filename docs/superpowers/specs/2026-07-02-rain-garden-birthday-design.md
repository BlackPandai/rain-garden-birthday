# Rain Garden Birthday 设计文档

## 概览

`rain-garden-birthday` 是一款手机优先的网页解谜小游戏，用作送给恋人的生日礼物，同时兼容桌面浏览器访问。主要体验目标是在手机上通过滑动查看同一场景的不同视角，并点击具体物件推进谜题。玩家在阴雨中的江南园林别墅里探索，由一只名叫“摸鱼”的英国可卡犬引导。游戏开头有轻微神秘感，但不走恐怖或强悬疑路线；随着谜题推进，玩家逐渐发现整座园林、线索和机关都是一场温柔寻礼。

首通目标时长为 15-25 分钟。最终交付形式应是可部署的静态网页链接，让寿星优先在手机浏览器中打开，也能在电脑浏览器中正常游玩。可以准备本地备份，但正式体验以 hosted URL 为主。

## 核心体验

整体气质是“雨中寻礼”，不是恐怖解密。开场可以安静、略带神秘：窗上的雨声、玄关的湿爪印、伞边的小卡片，以及看似被刻意摆放的物件。玩家解开谜题后，氛围逐渐变暖，最终反转为生日惊喜。

设计重点是亲密、温柔、轻盈和私人感。摸鱼不是普通提示按钮，而是情绪角色和引导角色。它会留下爪印、叼来卡片、看向关键物件、趴在重要线索旁边，或者在玩家接近答案时做出反应。

## 现实场景

游戏应尽量贴近生日当天入住的江南园林别墅。已知可用空间包括：

- 玄关
- 客厅
- 卧室
- 池塘
- 窗边
- 庭院

游戏里的动线应对应现实中自然会走过的路线。这样结局给出的礼物线索可以直接指向别墅里的真实位置。

## 整体结构

采用已选定的方案 A：单主线实体礼物 + 通关后庭院彩蛋礼物。

主线一定能完成，不会因为玩家选择不同而卡死。玩家按固定动线收集数字线索，最终在卧室输入八位线索打开小木盒，获得唯一主线实体礼物提示。主线完成后，游戏通过返回庭院的含蓄入口开放一个彩蛋：庭院里出现迪士尼游轮船票线索，点击后弹出一张船票图片，作为虚拟礼物揭晓。

游戏不再保留三结局作为玩家可见目标，也不再使用隐藏印记决定最终礼物。场景中的不同热点仍保留探索感和情绪差异，但它们只影响当下反馈，不改变最终礼物类型。

## 场景流程

### 1. 玄关：湿伞与爪印

玄关是教学场景。玩家看到湿伞、门垫上的爪印，以及摸鱼留下的第一张卡片。这里建立基本交互，也让玩家理解摸鱼会带路。

谜题形式：观察爪印方向、伞柄挂饰和短卡片，解开进入下一个场景的线索。

### 2. 客厅：暖灯与影子

玩家调整灯光、照片或摆件，让墙上的影子组成一句生日线索。这个场景强调日常陪伴和屋内暖意。

谜题形式：点击调整物件、对齐影子、显示一句短祝福或密码。

### 3. 窗边：雨痕与花窗

玩家观察窗上的雨痕、江南花窗纹样，以及摸鱼看向的方向。这个场景连接窗内回忆和窗外庭院，为最终密码与庭院彩蛋埋下情绪伏笔。

谜题形式：匹配雨痕和花窗图案，得到顺序或短密码。

### 4. 庭院与池塘：倒影与石径

玩家根据池塘倒影、石径顺序和摸鱼停留的位置解开主线机关。这个场景承担最强的江南园林感，也为通关后的船票彩蛋预留空间。

谜题形式：倒影匹配、石径顺序、按雨水和水面提示选择物件。

### 5. 卧室：灯下的小秘密

卧室是情绪收束和最终开盒场景。玩家把前面得到的数字线索拼成八位输入，打开小木盒后揭晓唯一主线实体礼物。该礼物放在卧室中，是生日当天最稳定、最明确的主线惊喜。

## 礼物结构

### 主线礼物：卧室中的实体礼物

触发方式：玩家完成主线场景，收集四段数字线索，在卧室小木盒输入 `07070522`。

礼物类型：实体礼物。

推荐现实位置：卧室中容易被找到但不直接暴露的位置，例如床边、书桌、柜上或小木盒旁。游戏结尾应明确指向卧室中的实体礼物，避免玩家通关后仍找不到。

呈现方式：输入正确密码后播放礼盒开启特效，再出现主线礼物页。主线礼物页只保留一个温柔、确定的生日惊喜文案和兜底提示按钮，不显示任何分支标签或数量提示。

### 彩蛋礼物：庭院中的迪士尼游轮船票

触发方式：玩家完成主线实体礼物后，点击 `回到庭院，再听一会儿雨` 返回庭院。庭院中出现新的彩蛋热点，例如 `看池边的船票信封` 或 `看灯笼下的蓝色纸片`。点击后弹出船票图片。

礼物类型：虚拟礼物。

礼物内容：一张迪士尼游轮的船票。

推荐现实/游戏位置：庭院或池塘边，不放置怕受潮的实体物。游戏中用防水信封、蓝色纸片、船形倒影、灯笼下的卡片等元素暗示彩蛋入口。

呈现方式：弹窗居中展示一张船票图片资源，设计为可被玩家截图或保存的纪念票面。弹窗包含关闭按钮和一句摸鱼提示，例如：“摸鱼把爪子搭在船票边，像是已经选好了登船那天。” 船票图片应作为静态资源进入项目，例如 `assets/disney-cruise-ticket.png`。

## 解锁规则

1. 首次游玩只能走主线，最终在卧室获得实体礼物。
2. 主线实体礼物完成后，才开放庭院彩蛋入口。
3. 彩蛋入口不需要再次输入 `07070522`。
4. 彩蛋船票可以重复打开，方便玩家重新查看或截图。
5. 点击 `从头开始` 会重置主线状态和彩蛋状态，恢复为未通关体验。

彩蛋礼物必须被主线礼物完成状态硬性门控。实现时应至少有两个保护点：

1. 渲染保护：庭院彩蛋热点只有在 `mainGiftUnlocked` 或等价状态为 `true` 后才出现在画面上。
2. 行为保护：即使通过异常状态、旧 DOM 或手动触发点击事件，也必须在点击处理里再次检查主线礼物是否已完成；未完成时不打开船票弹窗，只给出温柔反馈或忽略。

## 摸鱼的作用

摸鱼是引导角色、提示系统和情绪锚点。它不应表现成普通的“提示按钮”。

预期行为：

- 在入口或转场附近留下湿爪印。
- 叼来小卡片或纸片。
- 看向关键物件。
- 玩家卡住时趴在重要线索旁。
- 对回忆、陪伴、旅行暗示类物件有不同反应，但这些反应不改变最终礼物。
- 主线完成后回头看向庭院，暗示雨里还有没说完的话，引导彩蛋船票。

提示分层：

1. 第一层：摸鱼看向相关区域。
2. 第二层：摸鱼叼来一张带诗意提示的卡片。
3. 第三层：卡片给出更直接的操作说明。

## 错误处理

游戏不惩罚玩家。输错密码或顺序时，只给温柔反馈，例如“摸鱼歪了歪头，好像不是这个顺序。” 不设置失败状态。

现实礼物线索必须有兜底。主线礼物页除了诗意提示，还应有类似“让摸鱼说得更明白一点”的按钮。点击后给出更明确的卧室位置，避免生日当天因为线索太含蓄而找不到实体礼物。彩蛋船票弹窗应直接展示票面图片，不需要额外解谜。

## 数字线索、现实联动与最终开盒机制

主线密码获取改为“网页线索 + 卧室实体手写卡片”的现实联动谜题。网页负责保证玩家一定能收集到四段数字线索；实体卡片负责给出最终排序和情绪落点。这样密码获取更有仪式感，也能让现实卧室参与寻礼，而不是只在网页里完成输入。

最终密码仍固定为 `07070522`。这串数字来自收礼人的月日 `0707` 和摸鱼生日的月日 `0522`，但网页中不直接说“生日”“密码答案”或“把生日拼起来”。

数字线索不绑定到某一个可选热点，以免玩家因为选择不同而漏掉密码。每个场景点任意一个具体物件后，都会出现该场景的主线完成反馈，反馈中包含一段含蓄数字暗示：

1. 玄关给第一段 `07`：门边留下“一枚圆”和“一道七字折角”。
2. 庭院给第二段 `07`：天上和水里的月亮互相映照，暗示同一段痕迹出现两遍。
3. 客厅给第三段 `05`：小窝边的纸角露出“五月的开头”。
4. 窗边给第四段 `22`：信封边缘有两个相同的小数挨在一起，像并排的爪印。

卧室不直接给完整排序规则，而是引导玩家在现实卧室中寻找一张手写卡片。网页文案可以类似：

> 小木盒没有锁孔，只有八个空格。摸鱼把爪子搭在床边那张纸上，像是在说：最后一步，不在雨里，在你手边。

实体手写卡片承担最终排序。卡片上可以写得诗意但足够公平，例如：

> 先写下被雨等到的人，  
> 再写下跟着你回家的小尾巴。  
> 门边和水里，是同一个她；  
> 五月开头与并排爪印，是同一个它。

玩家根据网页中收集到的四段数字和实体卡片的排序规则，得到 `0707 + 0522 = 07070522`，再回到网页输入八位线索。

输入错误时使用分层反馈：

1. 第一次错误：木盒没有动，雨声像漏掉了一拍。
2. 第二次错误：摸鱼把纸往手边推了推，暗示“最后一步在纸上”。
3. 第三次及以后：摸鱼点出两组归属：先是被雨等到的人，再是一路跟回家的小尾巴。

第一次成功输入后，游戏记录主线礼物已经打开，并开放庭院彩蛋入口。之后玩家回到庭院点击彩蛋入口时，不再重复要求输入密码。

生日当天需要提前准备一张实体手写卡片，放在卧室中和小木盒/主线实体礼物有自然关系的位置，例如床边、书桌或柜上。卡片不应直接写出 `07070522`，但应足够让玩家在两次错误提示后能解出答案。

## 礼物呈现与隐藏性

游戏文案不能明确提示“三个结局”“3 份心意”“隐藏结局”“还有另外两个”等旧结构。新的表达应聚焦两层惊喜：卧室主线实体礼物是正式终点，庭院船票是通关后的雨中彩蛋。

主线礼物后的返回按钮应避免“寻找隐藏结局”这类系统感表达，推荐改成类似：

- `回到庭院，再听一会儿雨`
- `沿着摸鱼的脚印回去`

主线礼物后提示也应保持含蓄，例如：“摸鱼没有急着离开。它回头看了一眼雨里的庭院，像是那里还有没被雨声说完的话。” 玩家可以感到仍可探索，但不会被直接告知彩蛋内容。进入庭院后，彩蛋热点可以比普通热点更有仪式感，例如蓝色微光、船形倒影或信封边缘露出的海蓝色。

## 网页与移动适配要求

游戏以手机网页为主要展示目标，同时兼容桌面浏览器：

- 手机端允许通过左右滑动平滑移动同一张场景图的不同视角，这是主要探索方式。
- 手机端不显示左右切换按钮，滑动应跟手、平滑，热点必须跟随背景移动。
- 桌面端作为兼容体验，场景图铺满或居中展示浏览器，不显示左右切换按钮。
- 点击区域足够大，热点必须落在具体物件上。
- 除最终八位线索外，尽量少输入文字。
- 场景文字简短。
- 能在常见桌面浏览器、手机浏览器和应用内浏览器中打开。

最终产物应是可部署的静态网站。核心体验不依赖后端。

## 测试计划

生日当天前至少测试以下内容：

- 首通时长稳定在 15-25 分钟。
- 主线无需额外说明即可完成。
- 主线实体礼物能稳定在卧室打开，不受玩家热点选择影响。
- 主线完成后能通过含蓄入口回到庭院。
- 庭院彩蛋热点只在主线完成后出现。
- 庭院彩蛋点击处理必须校验主线礼物完成状态，不能在未获得主线礼物时打开船票。
- 船票弹窗能稳定打开、关闭，并展示迪士尼游轮船票图片。
- 现实实体礼物提示能准确指向卧室位置。
- 实体礼物放在室内。
- 迪士尼游轮船票作为虚拟礼物，不需要在庭院放置怕受潮的实物。
- 部署链接能在寿星手机上正常打开。
- 音效、图片、输入框和返回流程在手机浏览器中正常。

准备一个生日当天兜底方案：保留一份私人说明，记录卧室实体礼物的位置、船票图片的含义和领取方式。若网络、浏览器或谜题临时出问题，可以保证惊喜不被卡住。
